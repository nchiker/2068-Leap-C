# Leap-C 1.0.0

**A C computer for the Timex Sinclair 2068.** Leap-C replaces the TS2068's two ROMs with a full-screen C editor and a C compiler that runs on the machine: type a program, `RUN` compiles it to native Z80 code (about 13 ms a line) and runs it. This is the first release. It follows two public betas and replaces 1.0.0-beta.2. It is qualified on emulators; it has not yet been run on a physical TS2068.

**Start here:** [docs/EMULATORS.md](https://github.com/nchiker/2068-Leap-C/blob/v1.0.0/docs/EMULATORS.md) (setting up Fuse, ZEsarUX or TSRun), [docs/USER_GUIDE.md](https://github.com/nchiker/2068-Leap-C/blob/v1.0.0/docs/USER_GUIDE.md), [docs/manual/](https://github.com/nchiker/2068-Leap-C/tree/v1.0.0/docs/manual) (the user's manual, eight parts; also a Word edition in the assets), [CHANGELOG.md](https://github.com/nchiker/2068-Leap-C/blob/v1.0.0/CHANGELOG.md). No install at all: [run it in your browser](https://nchiker.github.io/TSRun/?rom=leapc) (TSRun; tapes do not load there).

## What changed since 1.0.0-beta.2

- **A report is one row.** After `RUN`, `FREE` or a tape command the report takes only the bottom row (row 23), so the rest of the program's screen stays visible. `RUN` reports `EXIT n`, `ERROR n MESSAGE`, `RUNTIME ERROR n MESSAGE` or `BREAK`. The line is no longer printed: the cursor goes to it, and the status row shows `LINE n/m` once you press a key. The image size, the heap and the name of an undeclared identifier are no longer shown; `FREE` shows the source's size and the room left.
- **The version** (`2068 LEAP-C 1.0`) shows on the status row from power-on until the first key.
- **`NULL` is predefined** as `0`. A program may still define it itself once, or `#undef` it.
- **`SAVE` and `tape_save` leave about a second of silence** between the header and the data block, as the TS2068's own ROM does, so tools that convert tape recordings see two blocks.
- **Fixed: hi-res colour.** In `mode(1)`, `plot` and `draw` coloured the wrong pixel row (all but 24 of the 192 rows). Platform delta D22.
- **Fixed: scrolling.** Output that scrolls cleared each new bottom row in white paper instead of the program's colours.
- **Fixed: `p`, `q` and `g`** sat one pixel row high, so `p` looked like a capital `P`. Platform delta D24 (font data only).
- **For hosts that drive the ROM** (the Leap IDE, test harnesses): the emulator pack carries `symbols/leapc_home.sym` and `symbols/leapc_exrom.sym`; two new labels, `STMT_DO.cond` and `SH_WAIT_KEY.key_ret`. The stable names are listed in [CHANGELOG.md](https://github.com/nchiker/2068-Leap-C/blob/v1.0.0/CHANGELOG.md).
- **Documentation:** the user's manual corrected and completed after an audit against the ROM; the screenshots retaken.
- The ROMs have new hashes (below). Tapes are unchanged in format: tapes saved by beta.2 load, and beta.2 loads 1.0.0's.

## What Leap-C does

- **The language:** a documented subset of C89: `char` (unsigned), `int`, `unsigned`, pointers, multi-dimensional arrays, `struct`, `enum`, `typedef`, pointers to functions, recursion, every operator and statement (`switch`, `goto` too), static initialisers, `#define`, and `float`/`double` in the Sinclair 5-byte format with `printf("%f")`. Anything outside the subset is a compile error (`NOT SUPPORTED`), never a miscompilation.
- **The library**, built in, no `#include`: text, colour and `printf`; the keyboard (`getkey`, `inkey`, `gets`); graphics (`plot`, `draw`, `point`, sprites, the hi-res colour mode); the AY sound chip (`beep`, `sound`); `frames`, `pause`, `rand`; strings and memory; `malloc`/`free`; ports; cassette data (`tape_save`, `tape_load`).
- **Libraries from tape:** `LIB "shapes"` loads an assembly library (1 KB) whose functions are then called like the built-in ones; 16 fixed ROM service slots keep libraries working across ROM updates.
- **The editor:** full screen, lines up to 127 characters that wrap, C keywords in bold, the C characters the TS2068 lacks on SYMBOL SHIFT + Y U F G S A H D (`[ ] { } | ~ ^ \`), compile errors that put the cursor on the error's column, runtime errors and BREAK reported at the failing function's line.
- **Cassette:** `SAVE`, `LOAD`, `VERIFY` of program source in the TS2068's standard signal; `tools/c2tape.py` makes a tape from a `.c` file on a PC.
- **Capacity** on a 48 KB TS2068: about 18 KB of source, 19 KB of compiled code and data, a heap of up to 18 KB. Exact limits: Appendix E of the manual.

## How it was qualified

On **Fuse 1.9.1** (unmodified; the TS2068's real 60 Hz frame) and **ZEsarUX 13.0 with an EXROM patch** (50 Hz), headless, by `make qualify` on 2026-11-01. Emulators only. Every step passes; no ROM defect was found. The per-step record, including the steps that were rerun by hand, is in [docs/milestones/M11-release.md](https://github.com/nchiker/2068-Leap-C/blob/v1.0.0/docs/milestones/M11-release.md).

- **Compiler and shell:** lexer 113/113, declarations 215/215, shell 44/44; the workflow suite 47/47 cases and the executable corpus 1,164/1,164 programs through the shell's `RUN`; the float core 5,451/5,451 bit-exact against the model; power-on memory 949/949.
- **Cassette:** 30/30 on real tape signals both ways (all 33 cases with the fast tape).
- **Fuse:** boot, keyboard, typed programs 39/39, BREAK, frames, `SAVE` recorded and loaded back, WAVs, the library from tape, and 1,015 corpus programs LOADed from their tapes by Leap-C's own loader and RUN (7 sessions, 824,529 frames).
- **Timing:** Fuse and ZEsarUX agree within a factor of 1.006 to 1.074.
- **Hardware kit:** its verification with a 30-minute soak, H1-H11, passes on both emulators.
- **Tape tolerance** (`tools/tapetol.py`): 67 of 71 distorted test tapes accepted (beta.1: 54), as in beta.2.
- **RAM patterns and capacity:** warm RAM 1,164/1,164; random power-on RAM (`random:7`) passes on rerun; the capacity measurements pass; `make check` passes.
- **ROM coverage** (`build/romcov.md`): HOME 7,536 of 7,552 instructions (99.8%) and all 440 routines entered; EXROM 3,345 of 3,362 (99.5%) and all 154 routines.
- Reproducible builds; CI builds every commit.

## Known limitations

- **Not yet run on a physical TS2068.** The hardware kit and checklist are ready; results are very welcome.
- **ZEsarUX:** the downloadable ZEsarUX 13.0 shows a blank screen: build 13.0 with Leap V2's small EXROM patch ([EMULATORS.md §3](https://github.com/nchiker/2068-Leap-C/blob/v1.0.0/docs/EMULATORS.md#3-zesarux-130-with-the-exrom-patch)), or use Fuse. ZEsarUX cannot write `SAVE` to a tape file (only Fuse saves), and runs the TS2068 at 50 Hz (timings in frames 20% longer).
- **TSRun** (browser): tapes do not load; `SAVE` cannot be recorded.
- **The language:** no `long`, `union`, `volatile`, struct parameters, returns or assignment, initialisers on local arrays or structs, function-like macros, `#if`, user variadic functions, maths library, or `printf` flags and `%e`/`%g`. Integer division by zero gives 0. `float` is not IEEE. The limits of memory and nesting are in Appendix E of the manual.
- **`draw` with an end off the screen** clamps that end to the screen edge, which changes the diagonal's slope. `plot` off the screen draws nothing.
- **Keyboard legends:** the keys for `[ ] { } | ~ ^ \` show BASIC keywords on a real TS2068.
- Leap-C reads only its own tapes (TS2068 BASIC and Leap V2 tapes give `BAD TAPE VERSION`).
- Other emulators are untested.
