# Leap-C 1.1.0

**A C computer for the Timex Sinclair 2068, now also as a cartridge.** 1.1.0 adds the **runtime cartridge**: a compiled Leap-C program that runs from the DOCK of a **stock TS2068**, with the stock ROMs installed and no editor or compiler on board. Everything else is 1.0.0's: **the emulator ROM images are byte-identical to 1.0.0's**, and the banner still reads `2068 LEAP-C 1.0`. It is qualified on emulators; it has not yet been run on a physical TS2068.

**Start here:** [docs/CARTRIDGE.md](https://github.com/nchiker/2068-Leap-C/blob/v1.1.0/docs/CARTRIDGE.md) (running and making a cartridge), [docs/EMULATORS.md](https://github.com/nchiker/2068-Leap-C/blob/v1.1.0/docs/EMULATORS.md) (setting up Fuse, ZEsarUX or TSRun for Leap-C itself), [docs/USER_GUIDE.md](https://github.com/nchiker/2068-Leap-C/blob/v1.1.0/docs/USER_GUIDE.md), [docs/manual/](https://github.com/nchiker/2068-Leap-C/tree/v1.1.0/docs/manual), [CHANGELOG.md](https://github.com/nchiker/2068-Leap-C/blob/v1.1.0/CHANGELOG.md). No install at all: [run it in your browser](https://nchiker.github.io/TSRun/?rom=leapc) (TSRun; tapes do not load there).

## What's new: the runtime cartridge

- A **`.dck`** (for emulators) and a flat 64 KB **`.bin`** (for a physical cartridge, e.g. a PicoROM) that run one compiled program on a stock TS2068: `fuse --machine ts2068 hello.dck`, or ZEsarUX with its stock `ts2068.rom` and `smartload hello.dck`.
- The program is compiled by the **release** ROM (this repository's `make cart PROG=x.c [LIB=name]`, which uses ZEsarUX, or any host that follows the image format in CARTRIDGE.md, such as the Leap IDE) and carries the ROM **identity `$E90E`** (CRC-16/CCITT-FALSE of the release HOME then EXROM). The cartridge refuses any other with `NO PROGRAM`.
- After the program: the one-row report (`EXIT n`, `RUNTIME ERROR n MESSAGE`, `BREAK`), then a key runs it again from a cold start.
- The cartridge's HOME keeps all 1,908 release labels at their release addresses (only `IO_KEY_SCAN_ROW` moved) and carries the release EXROM byte for byte. Images up to 24 KB are supported (16 KB in DOCK chunks 4-5, the rest in chunk 2).
- `make cart`, `make cart-demo`, `make test-cart`; `tools/cartpack.py` is the reference packer for other languages.
- Nothing else changed: the compiler, the shell, the library, the tapes and the documents are 1.0.0's.

## How it was qualified

**The cartridge** (`make test-cart` with `--fuse`, 2026-11-01, about 2.5 minutes): 160 of 160 cases pass. Emulators only: ZEsarUX 13.0 and Fuse 1.9.1, both with their stock TS2068 ROMs.

- **A, equivalence:** 115 programs (66 from `tests/lib`, 49 from `tests/doc`) run on the cartridge and by `RUN` on the release ROM: rows 0-22 (text, bitmap, attributes) and the row-23 report identical, apart from the expected differences below.
- **B, behaviour (25):** exit values, runtime errors 1, 4, 6 and 3, BREAK, a restart from cold (the image is re-copied: a static counter reads the same each run), float, `beep`/`sound`, `mode(1)` with and without `#pragma hires` and refused, libraries (shapes and testlib), a 17,008-byte image continuing into DOCK chunk 2, and `NO PROGRAM` for no image, a wrong identity, a wrong CRC, truncated blocks, a wrong format and a damaged byte in chunk 2, with key retries.
- **C, port audit (6):** `$F4` is written only with `$03`, `$33`, `$37` and `$43`; `$FF` only `$00` (or `$02` for hi-res); bit 7 is never set.
- **D, hand-off (5):** at the entry, IM 1, interrupts on, SP `$61FE`, `$F4` `$43`, `$FF` `$00`; the IM 1 handler run before the cartridge's `di` returns and the program runs, also with BREAK held.
- **E, Fuse (9 programs):** the screens are identical to ZEsarUX's.

Expected differences from `RUN`: `malloc`'s addresses (no source: the heap starts at an empty store's end, `$7802` against `$7868` for one program); `PEEK($0000-$0007)` reads the cartridge's header; UDGs are blank at every start.

**The emulator ROMs** are 1.0.0's and were qualified there ([docs/milestones/M11-release.md](https://github.com/nchiker/2068-Leap-C/blob/v1.1.0/docs/milestones/M11-release.md)). The regression rerun for 1.1.0: `make repro` reproducible OK (the four 1.0.0 hashes, and `leapc_cart_home.bin` `034e294d…` in both builds, identity $E90E); `make check` pass (with `tools/cart_check.py`); the fast suite pass, 0 failures; `make test-cart CARTTEST_ARGS=--fuse` 160/160 from a cold start; `make fuse` pass (corpus 1,017/1,017). Two test-tool defects found and fixed on the way: parallel Fuse workers built the Fuse shim to one path at once (now an atomic rename), and the `frames` check read Fuse's frame count and `FRAMES` with two shim commands, which Fuse could run frames between at a host load average of 15 (now one batch, answered between two frames).

The milestone report is [docs/milestones/M12-cart.md](https://github.com/nchiker/2068-Leap-C/blob/v1.1.0/docs/milestones/M12-cart.md).

## Known limitations

The cartridge's:

- **Not run on a physical TS2068, a physical cartridge or a PicoROM.** Fuse and ZEsarUX only; TSRun untested.
- **A known hazard:** an interrupt exactly between the stock ROM's jump to the cartridge and its first instruction (`di`), with BREAK held and a non-zero byte in stock RAM at `RUNNING` (`$5EB6`), would unwind to a run stack of 0. Forced in a test; not seen otherwise (`RUNNING` reads 0 after the stock boot).
- A program must be compiled by the release ROM (identity `$E90E`); the cartridge has no compiler, editor or source, reports no line number, and holds one program (24 KB at most).
- The expected differences above.

And 1.0.0's:

- **ZEsarUX:** the downloadable ZEsarUX 13.0 shows a blank screen with Leap-C's own ROM: build 13.0 with Leap V2's small EXROM patch ([EMULATORS.md §3](https://github.com/nchiker/2068-Leap-C/blob/v1.1.0/docs/EMULATORS.md#3-zesarux-130-with-the-exrom-patch)), or use Fuse. The cartridge runs on stock ZEsarUX. ZEsarUX cannot write `SAVE` to a tape file (only Fuse saves), and runs the TS2068 at 50 Hz.
- **TSRun** (browser): tapes do not load; `SAVE` cannot be recorded.
- **The language:** no `long`, `union`, `volatile`, struct parameters, returns or assignment, initialisers on local arrays or structs, function-like macros, `#if`, user variadic functions, maths library, or `printf` flags and `%e`/`%g`. Integer division by zero gives 0. `float` is not IEEE. Limits: Appendix E of the manual.
- **`draw` with an end off the screen** clamps that end to the screen edge. `plot` off the screen draws nothing.
- **Keyboard legends:** the keys for `[ ] { } | ~ ^ \` show BASIC keywords on a real TS2068.
- Leap-C reads only its own tapes (TS2068 BASIC and Leap V2 tapes give `BAD TAPE VERSION`). Other emulators are untested.
