# Leap-C 1.2.0

**A C computer for the Timex Sinclair 2068, with graphics, text, scrolling and the keyboard interrupt several times faster.** 1.2.0 takes the display code of 2068-Forth 2.0. `draw()` is 4.6 to 6.1 times faster, a printed character costs 590 T-states, and every program gains about 3% from a cheaper interrupt. The pixels, screens and glyphs are the same as 1.1.0's. The ROM images are new, the banner reads `2068 LEAP-C 1.2`, and the cartridge identity changes to `$F6E9`. It is qualified on emulators; it has not yet been run on a physical TS2068.

**Start here:** [docs/CARTRIDGE.md](https://github.com/nchiker/2068-Leap-C/blob/v1.2.0/docs/CARTRIDGE.md) (running and making a cartridge), [docs/EMULATORS.md](https://github.com/nchiker/2068-Leap-C/blob/v1.2.0/docs/EMULATORS.md) (setting up Fuse, ZEsarUX or TSRun for Leap-C itself), [docs/USER_GUIDE.md](https://github.com/nchiker/2068-Leap-C/blob/v1.2.0/docs/USER_GUIDE.md), [docs/manual/](https://github.com/nchiker/2068-Leap-C/tree/v1.2.0/docs/manual), [CHANGELOG.md](https://github.com/nchiker/2068-Leap-C/blob/v1.2.0/CHANGELOG.md). No install at all: [run it in your browser](https://nchiker.github.io/TSRun/?rom=leapc) (TSRun; tapes do not load there).

## What's new: the display on 2068-Forth 2.0's code

Platform deltas D25 to D29 ([platform/UPSTREAM.md](https://github.com/nchiker/2068-Leap-C/blob/v1.2.0/platform/UPSTREAM.md)). The reports are [M13-draw.md](https://github.com/nchiker/2068-Leap-C/blob/v1.2.0/docs/milestones/M13-draw.md) and [M14-display.md](https://github.com/nchiker/2068-Leap-C/blob/v1.2.0/docs/milestones/M14-display.md). All figures are T-states under ZEsarUX.

- **`draw()` is 4.6 to 6.1 times faster; `plot()` takes 25% less.** The line is 2068-Forth 2.0's: the screen address and bit mask are stepped from pixel to pixel, the Bresenham error is kept in the alternate registers, and the attribute is written where the cell changes. D25. An end off the screen is still moved to the edge, and `over(1)` still draws by exclusive-or.

  | | 1.1.0 | 1.2.0 | |
  |---|---:|---:|---:|
  | `draw(0, 100, 255, 100)`, 256 pixels | 369,298 | 60,702 | 6.1x |
  | `draw(100, 0, 100, 191)`, 192 pixels | 283,902 | 51,563 | 5.5x |
  | `draw(0, 0, 255, 191)`, 256 pixels | 388,184 | 81,691 | 4.8x |
  | `draw(10, 10, 100, 60)`, 91 pixels | 136,701 | 29,461 | 4.6x |
  | one `plot()` call | 1,366 | 1,029 | -25% |

- **Scrolling is 1.8 times faster.** Program output moves the screen in unrolled `LDI` runs and clears the new row directly. `GFX_SCROLL_OUTPUT_UP` takes 133,659 T, against 236,677. `GFX_CLEAR_ROW` on row 23 takes 7,603 T, against 33,152. D26.
- **Printing is faster.** The font is now in ASCII order, so a character is found with one subtraction (punctuation used to cost up to twice a letter). D28. `print` and `puts` hand each run of a string, up to a newline, to the screen in one call. D29. A printed character costs 1,467 to 2,933 T in 1.1.0 and 590 T now. `print("12345")` takes 3,437 T, against 8,256. `printf("%d", 12345)` takes 12,677 T, against 17,757. `putchar` of one character is still 1,141 T, against 1,857.
- **The interrupt is cheaper.** With no key down, one read of the keyboard ends the frame. An idle frame costs 225 T, against 2,028. That is about 3% of a 60 Hz frame, so every program gains about 3%. With a key held it costs 836 to 856 T, against 1,625 to 1,656. D27. Debounce, repeat and the BREAK latch are unchanged.
- **Same pixels, screens and glyphs.** The checks against 1.1.0:
  - `make lines`: 448 lines, on and off the screen, in both modes, with and without `over`, match a model of the 1.1.0 line (which was itself checked against the 1.1.0 ROM) byte for byte.
  - All 95 glyphs are byte-identical to 1.1.0's, checked from the two images.
  - Screens of newlines, a 40-character wrap, scrolling at the bottom, and `over(1)` and `inverse(1)` printing are identical.
- **Speed ceilings are tests.** `make lines` and `make display` (new, `tools/displaytest.py`) fail if a routine runs more than about 1.25 times slower than this build. On 1.1.0 all 8 of the original ceilings fail.
- **HOME has 607 bytes free**, against 481 in 1.1.0. The EXROM is unchanged in size.
- **The banner** on the status row from power-on to the first key reads `2068 LEAP-C 1.2`.
- **The user's manual, Part 7 example 11** ("Colour lines in high resolution") is replaced. It waits for a key in mode 1 and draws a band of 56 lines, so the colours can be seen. It no longer calls `paper(0)`, which left the screen black after `mode(0)`. It was proposed by the Leap IDE.

## Compatibility and what hosts must know

- **Programs and tapes.** Programs saved as source on tape load as before. Library tapes built for 1.x still load: the jump table at `$3FD0` and `LX_PLOT` are unchanged.
- **Cartridges.** The identity is **`$F6E9`**. A cartridge needs a program compiled by 1.2.0. Images made by 1.0.0 or 1.1.0 carry `$E90E` and show `NO PROGRAM`. Recompile them with the 1.2.0 ROM and pack them again. `python3 tools/cart_build.py --identity` prints the identity in the repository.
- **The `.sym` addresses moved.** No stable name changed (the list is in [CHANGELOG.md](https://github.com/nchiker/2068-Leap-C/blob/v1.2.0/CHANGELOG.md)). A host that reads the `.sym` files must take the 1.2.0 ones. TSRun and the Leap IDE need the new ROMs.
- **Internal labels** (none is a stable name):
  - `GFX_READ_PIXEL` now takes C = x, B = y.
  - `FONT_TABLE` is in ASCII order, codes 32 to 126.
  - `GFX_CLEAR_ROW` takes the attribute in A.
  - Removed: `MATH_COMPARE16`, `GFX_SCROLL_TEXT_UP`, `GFX_COPY_ROW_BITMAP`, `PUNCT_CHAR_TABLE`, `ROW_TABLE`, `IO_KEY_SCAN_ROW` and `GFX_SET_ATTR`.
- **The language, the shell, the tape format and the manual** are 1.1.0's, apart from example 11.

## Known limitations

- **Not run on a physical TS2068, a physical cartridge or a PicoROM.** Fuse and ZEsarUX only.
- **TSRun** (browser): tapes do not load; `SAVE` cannot be recorded. TSRun serves the 1.2.0 ROMs (`?rom=leapc`) but has not run a Leap-C cartridge.
- **The cartridge:**
  - A program must be compiled by the 1.2.0 ROM (identity `$F6E9`). The cartridge has no compiler, editor or source, reports no line number, and holds one program (24 KB at most).
  - A known hazard: an interrupt exactly between the stock ROM's jump to the cartridge and its first instruction (`di`), with BREAK held and a non-zero byte in stock RAM at `RUNNING` (`$5EB6`), would unwind to a run stack of 0. Forced in a test; not seen otherwise.
  - Expected differences from `RUN`: `malloc`'s addresses, `PEEK($0000-$0007)` reads the cartridge's header, and UDGs are blank at every start.
- **ZEsarUX:** the downloadable ZEsarUX 13.0 shows a blank screen with Leap-C's own ROM: build 13.0 with Leap V2's small EXROM patch ([EMULATORS.md §3](https://github.com/nchiker/2068-Leap-C/blob/v1.2.0/docs/EMULATORS.md#3-zesarux-130-with-the-exrom-patch)), or use Fuse. The cartridge runs on stock ZEsarUX. ZEsarUX cannot write `SAVE` to a tape file (only Fuse saves), and runs the TS2068 at 50 Hz.
- **The language:** no `long`, `union`, `volatile`, struct parameters, returns or assignment, initialisers on local arrays or structs, function-like macros, `#if`, user variadic functions, maths library, or `printf` flags and `%e`/`%g`. Integer division by zero gives 0. `float` is not IEEE. Limits: Appendix E of the manual.
- **`draw` with an end off the screen** clamps that end to the screen edge. `plot` off the screen draws nothing.
- **Speed:** `putchar` of a single character (1,141 T) and literal text in a `printf` format (`printf("12345")`, 5,032 T) still go a character at a time. The figures above are ZEsarUX's; the timings in frames are 20% longer at its 50 Hz.
- **Keyboard legends:** the keys for `[ ] { } | ~ ^ \` show BASIC keywords on a real TS2068.
- Leap-C reads only its own tapes (TS2068 BASIC and Leap V2 tapes give `BAD TAPE VERSION`). Other emulators are untested.
