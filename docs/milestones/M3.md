### 3.1 Program start and exit

`RT_RUN` keeps its Phase 1 contract (called by the shell, returns to it) and adds:

- **Start:** `RUN_SP`; the run state `RT_STATE` cleared (error and its address and line, the BREAK request, `NOBRK`, `rand()`'s state, the print position, inverse and over); the colours paper 7 / ink 0; an empty heap; `RUNNING`; `call main`.
- **End:** every end returns to the instruction after `call .main`. There `RUNNING` is cleared with interrupts off for that instant (a BREAK accepted just before it unwinds to the same place again: its interrupt wrote the same return address at `RUN_SP`). Then the error line, the AY volumes R8-R10 = 0, the normal display mode, the paging depth on entry, IX; A = 0 and HL = the status, or A = the error.
- **Deviations from `spec.md` §5.7 (recorded in v0.5):** the program runs on the caller's stack (setting SP = `$FF00` would overwrite the shell's return chain); static data is not copied at the start (the compiler writes it with its initial values and `RUN` always compiles first); all three AY channels are silenced, not only A; the display mode is set to normal unconditionally (no visible change when it already is: 6 B less than the test).

### 3.2 BREAK

- **The ISR (platform delta D4).** When `KBD_ISR_TICK` accepts a key it latches it as before; if the key is BREAK it then calls `RT_BREAKREQ`. V2's latch for its VM (`VM_ERROR_CODE`, `VM_HALTED`, 14 B) is gone; the delta is 8 B. The frames that accept no key run exactly V2's code.
- **`RT_BREAKREQ`.** No program running: returns (an ordinary key, the editor's). Otherwise it sets `BRK_HALT`; if `NOBRK` is 0 it takes the interrupted PC from the ISR's frame, enables interrupts and ends the program (runtime error 5) through `RT_ERROR`, which drops the ISR's frame with the program's stack.
- **Deferred sections.** `beep()`'s EXROM trampoline increments `NOBRK`. The platform's `AY_WAIT_FRAMES` ends early on `BRK_HALT` (the V2 maintenance behaviour), `AY_BEEP_PLAY` silences channel A, the trampoline pages the EXROM out, and `RT_NOBRK_END` stops the program.
- **Heap updates are not deferred** (deviation from `spec.md` §5.8, recorded in v0.5): the heap belongs to one run and the next start sets up a new one, so an interrupted `malloc` leaves nothing that must be consistent (tested: `tests/rt/break_malloc.c`, then a second run that allocates).

### 3.3 Runtime errors and their lines

Each error records an address in the failing code (`RT_ERRPC`):

| Error | Address | Line reported |
|---|---|---|
| 1 stack overflow (`ENTER`) | the code of the function being entered | that function's |
| 3, 4 library (`mode`, `beep`, `sound`, `itoa`, `sprite_get/put`) | the program's address of the library call (`LIB_CALLER`) | the function that called the library |
| 5 BREAK | the interrupted address in the image; in the ROM, the last library call | the function running, or the one that called the library |

`RT_ERRLOC` takes the newest record of the function → line table that starts at most 8 KB before the address (a function's code can continue into the next image region; the newer functions there start after it). Tested in all three cases, including a function in image region 2 (`tests/rt/error_line_region2.c`). "The failing function's call site" in `spec.md` §5.9 is read as the line where the definition of the function that was running starts: the table has no per-statement lines.

### 3.4 The library

48 functions, built on the retained platform wherever it has the service: text through `GFX_PRINT_STRING_ATTR` (wrapping, scrolling, attributes, over), the platform's ink/paper swap for `inverse`, `GFX_PLOT_CLIPPED`, `GFX_LINE`, `GFX_READ_PIXEL`, `GFX_CELL_ATTR_ADDR`, `GFX_SET_MODE`, `GFX_SPRITE_CAPTURE`/`DRAW`, `GFX_CLS`/`GFX_PAINT_ATTR`, `GFX_SET_BORDER`, the keyboard latch (`IO_READ_KEY`, `IO_READ_KEY_NONBLOCK`), `AY_BEEP_PERIOD`, `AY_WAIT_FRAMES`, the EXROM's `AY_BEEP_PLAY`, `MEM_FILL` (`memset`), `MEM_SHIFT_UP`/`DOWN` (`memmove`), `MATH_ABS16`/`NEGATE16`, and the helper core's `RT_UDIV` for number texts. New code: the argument loader (`LIB_ARGS`, which also records `LIB_CALLER`), the print position and colour state, `printf`, number texts, `gets`, the string functions, the heap.

Semantics and deviations are in `spec.md` §7.1. The deviations:

- `printf`: no flags; another conversion character prints the next argument as a character; **the return value is undefined** (C89 returns the number of characters; a counter did not fit the budget, §5).
- A program's own prototype of a library function declares a new function (C89 7.1.7 lets a program declare library functions itself).
- Pointer parameters are `void *` (any object pointer converts): passing an `int *` to `strcpy` is not diagnosed.
- `abs(-32768)` = -32768; `atoi` wraps; `itoa` is the common non-standard form (negative only in base 10).

### 3.5 The binding

The names are not declared in advance and are not reserved. `CX_PRIMARY` calls `LIB_BIND` when an identifier is undeclared (5 B in expr). `LIB_BIND` asks the EXROM (`CX_LIBFIND` → `LIB_FIND`: the identifier against 48 names) and, for a library name, builds the function type (return type, parameter types, `TFF_PROTO`; `printf` without a parameter list) and a defined, extern file-scope entry at the ROM address. Calls then check the argument count and types and convert, `void` results are refused, and library functions have addresses (tables of function pointers to them work). A program's own declaration of the same name is found first.

The search runs at compile time only, once per library name a program uses; it reads only the identifier in the line store and its table, so it satisfies bank rule 3 (it never touches chunk 6 and raises no error). Measured (built-in, including the trampoline's paging): 627 T for the first name (`cls`), 12,940 T for the last (`exit`), 12,853 T for an identifier that is not the library's: at most 3.7 ms, once per name a program uses.

## 5. Budget: the protocol applied (ledger L19-L23)

The library was built in HOME first and measured: **1,766 B against its 1,300 B** (466 over), with rtexit at 229 B against 200. Of the 1,766 B, 1,187 B were library code and **579 B the binding** (name table 390, signatures 12, search 52, declaration builder 125); the feasibility study had estimated "platform bindings 200-400 B". The protocol (`project_plan.md` §1.2):

1. **Shrink.** The declaration builder was rewritten (125 → 93 B: the parameter list encoded last-first, written straight into the zeroed node); `mode`'s argument check (−4), `cls` (−2), `RT_RUN` (−12: the line lookup always runs, the mode reset unconditional, `RUNNING` set from a known non-zero value). Smaller items were reviewed and kept (§10).
2. **Cold code to the EXROM.** The name table, the signatures and the search are compile-time data that only the binding uses, once per library name; they read only the source and their own table (bank rule 3). They moved to the EXROM (468 B with the entry jump), reached through `CX_LIBFIND` (12 B, page0's trampoline budget). The declaration stays in HOME, where E_NOMEM can be raised.
3. **Reallocation.** HOME: the library then measured 1,274 B; its unused 26 B covered rtexit's 17 B (L21) and the expr hook's 5 B (L22) (L23 −22). EXROM: the reserve is only 83 B above its floor, so the 468 B came from the shell's unused budget (L20): the shell keeps 2,432 B for Phase 5 against about 1,876 B of V2 shell glue to adapt (V2's 2,754 B less its 878 B of BASIC-only parts). Phase 7 returns 331 B to the EXROM when the tape block I/O moves to HOME (L1).
4. **Owner decision:** not needed. Both reserves are unchanged (HOME 532 B, EXROM 339 B).

### 6.3 BREAK in every state (`tests/rt`, harness `// break:`)

The harness holds CAPS SHIFT + SPACE down in the emulated keyboard (ZRCP `send-keys-event`) at a chosen moment; the real ISR scans, debounces and accepts the key. A breakpoint on `RT_BREAKREQ` records the interrupted address and `NOBRK`, so each case proves the state it tests. Every case runs with the shell's paging (depth 1) and checks afterwards: runtime error 5, the source line, the paging depth back to 1, SP and IX restored, the AY's volumes 0, the line store unchanged.

### 7.3 Compile speed

**13.63 ms per line** (48,080 T per line) over the whole executable corpus (9,945 lines; Phase 2: 14.42 ms over 8,912 lines; the target is 25 ms). The library's cases are short programs with calls, which compile faster per line than the generated expression cases. A program pays the name search (§3.5) once per library name it uses. The lexer is unchanged: 428.5 T per byte.

## 9. Design decisions and deviations

1. **The binding is lazy and the names are not reserved** (§3.5). A program's own prototype of a library name declares a new function (deviation from C89 7.1.7).
2. **Pointer parameters are `void *`** in the library's prototypes.
3. **The name table is in the EXROM** (ledger L19, bank rule 3), funded from the shell's unused budget (L20).
4. **`printf`'s return value is undefined**; no flags.
5. **Start/exit** (§3.1): the caller's stack, no static-data copy, all three AY channels silenced, the display mode reset unconditionally.
6. **Heap updates are not deferred from BREAK** (§3.2).
7. **Runtime error lines** are definition lines (§3.3); error 2 is not raised by any Release 1 function.
8. **Screen coordinates** are the platform's: y from the top.
9. **`inkey()`** returns the key latched since the last read, not the key held down.
10. **Library routines may use `AF'`** within a call (`spec.md` §5.1): the selector of the colour, over/inverse and sprite entries survives `LIB_ARGS` there. Nothing else uses the alternate set during a run.
11. **The platform's swap** `GFX_ATTR_SWAP + 4` is entered past its cell lookup for `inverse` (`GFX_ATTR_SWAP_HL`), so the library shares the platform's tested ink/paper swap instead of duplicating it.
12. **Tests changed** (purpose kept): `rand()`'s state moved from the platform's `RND_STATE` to the cleared run state (`LIB_RND`, 5 B less in `RT_RUN`); the built-in check and `helperbench` read `LIB_RND`. `exectest` sorts functions by address only (two library names, `memcpy` and `memmove`, share one).

## 10. Code audit

`make audit` (the z80-skills pattern scan) over `src/`; each hint in the new code was checked by hand: the two `cpir` (BC = 0: a search of up to 64 KB, the string's NUL found first), the carry after `inc b` in `LIB_BIND` (from the `srl` before it; `inc` keeps carry), the `di`/`ei` around clearing `RUNNING` and the `ei` in `RT_BREAKREQ` (IM 1 needs no `reti`), the page-local `LIB_PARAMS` and `GFX_LINE_X0..Y1` (asserted), the stack offsets of `LIB_ARGS` (+2), `RT_BREAKREQ` (+12: the ISR's four pushes and two return addresses; confirmed by the BREAK cases' reported lines) and `LIB_SPPUT` (+8).

Found and fixed during the phase (by the tests):

- `LIB_BIND` destroyed C, which `CX_PRIMARY` keeps as the namespace for its second lookup: the first library call compiled to `call $7E00`.
- The colour, over/inverse and sprite entries pushed their selector before `LIB_ARGS`, shifting the arguments by a word (now kept in `AF'`).
- `mode(1)` passed 4 to `GFX_SET_MODE` (`inc a` after `RTE_HIRES`).
- Harness: the BREAK "after N instructions" mode did not resume the run; a tuple sort compared entries with equal addresses.

Not changed: the platform's `AY_BEEP_PERIOD` has two forms depending on whether its table crosses a 256-byte page; D4's 6 saved bytes moved the table to `$0CFF`, which selects the longer form (+3 B). A pad byte would recover 2 B; not worth a layout dependency.

## 11. Remaining ROM and RAM risks

- **HOME has 4 B left in the library** and 0 B in rtexit, expr, lexer, symtab, codegen, preproc and helpers; decl and stmt 1 B each. The HOME reserve is 532 B (20 B above the floor). Phase 7 has its 340 B (tape block I/O) and Phase 5 the platform's 141 B (glyphs and key map, about 80-90 B estimated). Phase 8's "remaining library items" have no HOME bytes: any addition is paid by shrinking or goes to the owner.
- **The shell's EXROM budget is 2,432 B** after L20 (Phase 5). If the adapted shell needs more, Phase 7's 331 B (L1) and the EXROM reserve's 83 B above the floor are the next sources; the FP decision (Phase 8) decides 2,165 B more.
- **`printf`'s return value** costs about 15 B (a counter in the character output); a later phase can add it if a program needs it.
- **The heap** shares the region with the compile workspace and is rebuilt every run; Phase 4 measures its capacity at the limit with the rest of the capacity table.
- **The keyboard map** is still V2's: `[ ] { } | ~ ^ \` cannot be typed and have no glyphs (Phase 5). Library output of these characters shows spaces.
- **Testing** is on ZEsarUX only (Phase 9: Fuse, EightyOne, hardware). BREAK uses the emulated key matrix through the real ISR.
