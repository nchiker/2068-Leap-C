### 3.2 The budget overrun and how it was handled (`project_plan.md` §1.2)

1. **Shrink.** The first complete build measured declarations and types at **3,258 B**. A shrink pass, with the full corpus re-run after each step, brought it to 2,949 B:
   - initialiser lists keep their state in cells saved around nesting instead of an IX frame (266 → 208 B);
   - parameter types are stored last parameter first, so they are copied straight from the scope chain (no IX);
   - the member list's tail pointer starts at the head cell, so appending has no branch;
   - common sequences factored out (`NEXT_HL`, `DCL_SETTYPE`, `DCL_LOCAL`, `NEED_NAME`, `IS_BLOCK`, the 3-byte chained error exits);
   - the declaration paths restructured to share the global/storage/alias tail; specifiers return storage class and `const` in one register pair;
   - 8 jumps relaxed to `jr` (`tools/relax_jumps.py`; most remaining `jp`s go to the shared error exits).
   - Function definitions, blocks and statements (169 B) moved to the statements component, which `spec.md` §2.2 budgets for them.
2. **Move cold code to EXROM.** Not applicable: declarations write the image in chunk 6, and bank rule 3 keeps the compiler core in HOME.
3. **Reallocate** (ledger, `budget.toml`):
   - **L2:** the symbol table measures 295 B; 400 B of its 800 B go back to the reserve (105 B stay for Phase 2's labels).
   - **L3:** declarations and types +1,000 B. The 2,000 B base covers the declaration parser and the type system. M1.2 also delivers parts that `spec.md` §2.2 has no line for: initialisers with brace elision and the `[]` counting pass (400 B), static data allocation and string staging (122 B), and the parser support every later compiler part uses (marks and rewind, group skipping, cell save, the error exits: 215 B).
   - **Net:** the HOME reserve goes from 1,484 B to **884 B**, 372 B above the 512 B floor. No owner decision is needed (step 4 applies only below the floor).

**Shrink candidates kept open** (not needed now; for M1.3 if the reserve gets tight): a shared tag-lookup for `struct`/`enum` (about 40 B), table-driven specifier combinations (about 15 B), `TY_EQUAL` restructuring (about 20 B), an operator-class nibble in the precedence table to shorten `CX_BINOP`'s dispatch (about 15 B).

### 3.3 EXROM (8,192 B): 3,885 B used, the same size as M1.1

No M1.2 code is in the EXROM. Its bytes differ from M1.1 only because the editor's redraw cells moved with the new Leap-C cells. Reserve 556 B (floor 256 B).

### 4.2 Declaration cases: 105, all pass

**Method.**

- Each case is a C file in `tests/decl/` with expectation lines in comments.
- The harness writes it into the line store, pages the EXROM out and calls the production `CC_COMPILE`. No test hook exists for M1.2.
- `tools/decltest.py` then reads the compile workspace and the image regions straight from RAM. It decodes symbol entries, type nodes and struct member lists with the layout in `include/leapc_decl.inc`, and renders types in a compact notation (`*[10]int`, `fn(int,*char)int`, `struct s`).
- Block and prototype scopes are captured at every `SCOPE_CLOSE` (a breakpoint), before their entries are reclaimed.

**Checked per case:** kinds, types, sizes, values (addresses, frame and argument offsets, enum values, member offsets), SF flags, struct layouts, static data bytes, data addresses, frame size, and that no error occurred. **For the Phase 4 capacity table.**

- **Workspace.** It is the RAM between the end of the source and `$C000`. With 6 KB of source, about 12 KB is free: roughly 900 globals with 4-character names.

## 8. Design decisions and deviations (recorded, not silent)

1. **Two-ended workspace.** `spec.md` §3.2 says the workspace "grows down from the top of the source region". It does, for everything that lives for the whole compile: file-scope symbols, type nodes and struct members.
   - Block and prototype scopes use a second stack that grows **up** from the end of the source and is reclaimed when a scope closes.
   - This lets file-scope entries and type nodes be created while blocks are open (block-scope `extern`; M1.3's implicit function declarations) and still outlive the block.
2. **Type handles.**
   - A type is 16 bits: either a scalar base with its pointer depth (no memory at all), or a node address.
   - Pointer types are canonical (each node caches its pointer type), so most type comparisons are a 16-bit compare. Arrays and functions compare structurally.
   - **Limit:** 15 pointer levels on a scalar base (C89 requires 12); more gives `E_NESTING`.
   - Function nodes list the parameter types **last parameter first**. M1.3 reads parameter *k* at slot *n − 1 − k*.
3. **Declarators are parsed by re-scanning.** For `( inner ) suffixes`, the inner part is skipped, the suffixes are applied, and the lexer rewinds to the inner part (`LEX_MARK`/`LEX_RESTORE`, possible because the lexer reads the line store in place). Each token is parsed once; skipped tokens are lexed twice.
4. **Names come from the source text.** `TOK_PTR` records each token's first byte, so a declared name is copied from the source when its entry is made, with no name buffer.
5. **Static storage is allocated at the first declaration of a complete type.** That includes `extern` declarations, so every object has its address from the start and no fixups are needed for objects.
   - An `extern` object that is never defined therefore behaves as if defined with zero value; C would give a link error. Single translation unit, so documented, not detected.
   - An `extern` of incomplete type gets storage when a later declaration completes it.
6. **`[]` arrays with initialisers use a counting pass.** The initialiser is parsed twice: first with nothing stored or allocated, to count the elements, then for real after a rewind.
   - **Limit:** a `struct` or `enum` *defined inside* such an initialiser (in a cast or `sizeof`) would be defined twice and gives `E_REDEF`. This is legal but very unusual C.
7. **The compiler writes initial values straight into the image and zeroes everything else.** `spec.md` §5.7 lets program start do this. Since every `RUN` recompiles, the image already holds the initial static data and program start needs no copy.
8. **`const`** marks the object (`SF_CONST`) when the declared object is not a pointer; for arrays, their elements are const.
   - Pointer-level `const` (`char *const p`) and `const` through a typedef are accepted and not tracked.
   - `spec.md` §4.2 requires enforcement only for direct assignment to a `const` object; M1.3 enforces it with this flag.
9. **Interim behaviour until M1.3/Phase 2** (`E_NOTSUP` or `E_UNDECL` now; the features are in the spec and are not reduced):
   - statements other than blocks and `;` inside function bodies;
   - initialised automatic objects (scalars in Phase 2; aggregates stay "not supported" per `spec.md` §4.7);
   - function addresses as static initialisers;
   - calls, assignment, `++`/`--` and comma, even inside `sizeof`;
   - implicit function declarations.
10. **Other choices.**
    - `int a[];` at file scope with no initialiser and no `extern` is `E_INCOMPLETE`; C89 would complete it as `int a[1]` at the end of the translation unit.
    - Enum values are not range-checked (any 16-bit value).
    - A trailing comma in an enum and empty initialiser braces `{}` are accepted (C99/GNU leniency); an empty struct is an error.
11. **The compiler uses IX.** `CC_COMPILE` preserves the caller's IX, so the Phase 6 shell sees no change. The compiler does not use IY.
12. **New error numbers** (`include/leapc_errors.inc`):
    - declaration 20-29;
    - type 40-42;
    - expression 50-53;
    - limit 90-92;
    - memory 100-101.

    The message texts belong to Phase 6.
13. **Placement of shared code.**
    - The constant-expression evaluator is counted in the expressions component: it is the parser M1.3 extends.
    - Folding is counted in the code generator, which `spec.md` §2.2 lists with "constant folding".
    - Function bodies and blocks are counted in statements and functions.

## 9. Code audit

**Pattern scan.** `make audit` runs the z80-skills pattern scan over `src/`, and every hint in the new files was checked by hand:

| Hint | Finding |
|---|---|
| `stack-delta-at-exit`, `stack-pointer-trick` | The deliberate under-the-return-address protocols: `SCOPE_OPEN`/`CLOSE`, `CELLS_SAVE`/`LOAD`, `LEX_MARK`/`RESTORE`, `CX_PUSHX`/`POPY`. Every other flagged exit pops exactly what its routine pushed |

| `call-followed-by-ret` | `PARAMS` ends `call SCOPE_CLOSE; ret`. A tail `jp` would break `SCOPE_CLOSE`'s stack protocol |
| `dynamic-vector-dispatch` | `CALL_HL` (allocator and specifier dispatch), `CX_PUSHX`/`POPY` returns |

**Bugs found during M1.2 and fixed:**

- `TY_DEREF` clobbered the element count in the `[]` counting pass.
- A first version of the cell save helpers crossed with their callers' pushes (caught by the corpus).

**Register contracts.** Every routine states In / Out / Destroys, and the callers were checked against them.
