### 2.3 `rand()` / `srand()`

- **Generator:** the 16-bit xorshift with shifts 7, 9, 8 (period 65,535). The Z80 sequence was verified equal to the reference xorshift for every non-zero state.
- **Results:** `rand()` returns 0..32767 (`RAND_MAX`).
- **Seeding:** `srand(n)` restarts the sequence; seeds 0 and 1 give the same one (state 0 is a fixed point of xorshift, so it is mapped to 1).
- **Program start:** C89 7.10.2.2 requires every run to begin with the sequence of `srand(1)`. `RT_RUN` clears the state (+5 B).
- **Calling convention:** both follow the C ABI (argument on the stack, result in HL). The library binding that lets programs name them comes in Phase 3.
- **Tests:** helperbench checks the first 64 values after program start and after `srand` of 0, 1, 12345 and 65535 against the model, and the stack contract of `srand`. A built-in check confirms that `RT_RUN` resets the state.

| | V2 `MATH_RND16` | `LIB_RAND` |
|---|---:|---:|
| HOME bytes | 87 | 36 (with `srand`) |
| T-states per call | 3,752-3,863 | 143 |
| Sequence | each value is the previous one shifted by one bit | xorshift, full period |

### 3.1 Statement code

Single pass, as the spike laid it out; forward jumps are fixup chains (codegen.asm), backward jumps go to known addresses:

| Statement | Layout |
|---|---|
| `if (c) s` | `c / jp !c,L / s / L:` (with `else`: `jp E` over it) |
| `while (c) s` | `top: c / jp !c,out / s / jp top / out:` |
| `do s while (c);` | `top: s / cont: c / jp c,top / out:` |
| `for (i; c; n) s` | `i / top: c / jp !c,out / jp body / step: n / jp top / body: s / jp step / out:` (no step: `continue` goes to `top`; no condition: no test) |
| `switch (e) s` | `e / call RT_SWITCH / dw table / s / out:` |
| `break`, `continue`, `goto L` | `jp` added to the loop's or the label's chain (or straight to a known label) |

- **Conditions** are tested directly: a comparison or `!` leaves the flags and a single `jp cc` follows. A constant condition gives an unconditional jump or none.
- **The `switch` table** goes into the image's static data at the end of the body, so the code needs no jump over it. It is dense when that is smaller (highest − lowest ≤ 2n − 3), else sparse. `RT_SWITCH` dispatches the sparse form in about 60 T per case tried and the dense form in constant time.
- **Duplicate case values** are found while the body is parsed.
- **The case list** lives in the compile workspace: 6 B per case.

**Labels** are function-scope entries in the global area, chained from `FN_LABELS`. A `goto` to a label not yet seen is a fixup chain that ends with the line of its first use. At the function's end, `UNDEF_CHECK` reports an undefined label at that line.

**Local initialisers** compile as `object = expression` on the frame object, with the value's tail dropped, as for an expression statement. Arrays and structs with initialisers stay "not supported" (spec.md §4.7).

### 3.2 The function → line table

`FUNC_DEF` adds a record `[link][address][line]` to the image's static data for each definition; `RUN_FNLINES` points at the newest. The line is that of the definition's first token. Phase 3's runtime-error report uses it. The cost is 6 B per function, against spec.md's "about 4": a list costs less ROM than building an array at the end of the compile.

### 3.3 The preprocessor

It lives in the lexer's stream, so the parser never sees it:

- **Hooks.** `LEX_NEXT` passes each completed token to `PP_HOOK`, and a line end to `PP_EOL` when it is in a directive or a macro's replacement. The end-of-line token code moved out of the lexer.
- **Macros.** A macro is a 7-byte record pointing at its name and its replacement in the `#define` line itself. Nothing is copied.
- **Expansion.** Up to 8 macros nest; each level saves the lexer's position and the macro's name position (`PP_STACK`).
- **Self-reference.** A name being expanded stays an identifier (C89 6.8.3.4); `#define x (x + 1)` and `#define A B` / `#define B A` work as in C.
- **Rewinding.** The compiler rescans tokens: call arguments are marked and evaluated last first, declarators are parsed inside out, and a label is detected by look-ahead. A mark inside an expansion is the outermost macro's name plus the token's number in the expansion. `LEX_RESTORE` expands again and skips to it, so macros in call arguments and declarators compile as in C (`tests/pp/macro_arguments.c`, `macro_declarators.c`).
- **Directives.** They can come between any two tokens; `#define` keeps the parser's name and `IX` (`tests/pp/directives_anywhere.c`).
- **Lexer tests.** The lexer test hooks run the lexer with `LM_RAW` (test image only), so the M1.1 lexer suite still compares the plain token stream with the reference lexer.

## 6. The spike workloads

**Method** (`tools/stmtbench.py`, part of `make test`):

- The production ROM compiles `tests/spike/workloads.c`, the spike's C source with the arrays and a `main` that sets them up, and runs it once.
- Each workload is then called from a driver assembled into RAM exactly as the spike's driver did: interrupts off, the arguments pushed last first, the call, the pops. The T-states run from before the pushes to after the pops, and the results are checked.
- The reference is the spike's **mixed** form (`Mrst_C000`: its hand-assembled output from the same templates, locals inline, helpers by RST).

| Workload | Leap-C bytes | Spike bytes | Δ | Leap-C T-states | Spike T-states | Δ |
|---|---:|---:|---:|---:|---:|---:|
| `sum(255)` | 65 | 67 | −3.0% | 71,039 | 75,415 | −5.8% |
| `copy(dst, src, 256)` | 60 | 64 | −6.2% | 86,958 | 98,587 | **−11.8%** |
| `asum(100)` | 93 | 97 | −4.1% | 47,952 | 55,945 | **−14.3%** |
| `move(pts, 20, 3)` | 81 | 86 | −5.8% | 14,410 | 16,413 | **−12.2%** |
| `fact(7)` | 54 | 70 | **−22.9%** | 9,224 | 13,874 | **−33.5%** |
| **All** | **353** | **384** | **−8.1%** | **229,583** | **260,234** | **−11.8%** |

**The deviations beyond ±10% are all improvements.**

- **Operands.** The spike translated every binary operation the same way: push the left operand, load the right, pop. The real compiler keeps a deferred left operand in place and loads it after the right one (`ex de,hl`), and holds a computed one in HL (M1.3 §4.1). The spike's `push hl / … / pop de` around every operator becomes `ex de,hl` or nothing. In `fact`, `n <= 1` is `ld l,(ix+4) / ld h,(ix+5) / ld de,1 / rst CMPLT / jp c` (13 B; the spike needed 16), and `n * fact(n - 1)` needs no pushes for `n` (28 B; the spike needed 37).
- **Multiply.** `fact`'s multiply is the new register-only `RT_MUL` (step 1), about 30% faster than the V2 `MATH_MULTIPLY16` the spike called.
- **`return`.** It is one byte (`rst LEAVE`, owner's frame decision of M1.3); the spike's form took two.
- **Layouts.** The loop layouts are the spike's (`for`: `jp body` after the test, `jp step` after the body). The statement code reproduces the spike's byte for byte where the spike had no operator overhead (`--n`, `i++`, `s = 0`).

## 8. RST assignment: operation census

**Method** (`tools/rstcensus.py`):

- The production ROM compiles every executable case.
- The generated code is decoded instruction by instruction and each instruction is counted by kind. Counts are static (occurrences in the code), which decides code size.
- Two corpora: everything (296 programs, 130,596 B of code), and everything except the generated operator cases (156 programs, 22,816 B). The generated cases exercise every operator at every type and inflate the helper calls.

**Decision: the RST map is confirmed unchanged.**

- **The five vectors** (`LDI`, `STI`, `ENTER`, `LEAVE`, `CMPLT`) hold the most frequent helpers of real programs. Three of them have their whole body in the slot and two start there (spec.md §2.3).
- **No CALL helper earns a vector.** The most frequent one, `RT_MUL` (43), barely passes the least frequent RST, `STI` (41). Swapping them would save 4 B over 22.8 KB of code and slow every pointer store: `STI` runs inside loops and costs 49 T at its vector against 55 T by CALL (the spike's measurement). In the operator-dense generated corpus `RT_MUL` leads `STI` 237 to 169, a 0.1% size difference.
- **RST `$30`.** The largest single kind of code is the frame access (29% of the bytes of real programs). That is exactly what the optional size templates (`LDL`/`STL` at RST `$30`, spec.md §5.6) would shrink, so the census supports keeping RST `$30` reserved for them. Owner decision O3 is deferred; Phase 8 decides from the Phase 4 capacity table.

## 10. Design decisions and deviations

1. **The spike comparison's deviations are improvements** (§6): fewer bytes and fewer T-states than the hand-assembled mixed output.
2. **`switch` always orders its values as signed for the dense decision.** The dense table indexes modulo 2^16, so it is correct for unsigned values too. Only which tables count as dense differs for unsigned values above 32767.
3. **The function → line table is a list (6 B per function).** spec.md said "about 4 B": §3.2.
4. **Redefining a macro is an error even with an identical replacement** (C89 allows that case). `#undef` first. spec.md §4.8 v0.4.
5. **Limits:** 8 nested macro expansions and 255 tokens per expansion give "nesting too deep" (spec.md §4.10).
6. **Tests changed** (purpose kept, expectations updated):
   - `tests/decl/err/notsup_auto_init.c` → `notsup_auto_array_init.c`: automatic scalars are supported now, arrays are not.
   - `tests/experr/notsup_if.c` → `tests/stmt/if/notsup_if_now_supported.c`: the same program now runs.
   - Four declaration cases expected static data at `$DFFE`; the first function's line-table record now takes those 6 bytes, so they expect `$DFF8`. These are `tests/decl/init/static_local_init.c` and `tests/decl/scope/block_extern.c`, `repeated_block_extern.c`, `static_locals.c`.
7. **The lexer tests run with `LM_RAW`** (the plain token stream), set by the test hooks only.
8. **Labels and `case` records are not reclaimed during a compile** (workspace above).

## 11. Code audit

`make audit` (z80-skills `audit-z80` pattern scan) was run over `src/`, and every hint in the new code was checked by hand:

- `ldir` copies have fixed counts of 4, 5 and 7.
- The `jp (hl)` dispatches are the statement keywords, the directive handlers and `RT_SWITCH`.
- Flag tests survive the `ld`/`push`/`pop` that follow them: `PP_HOOK`, `PP_FIND_IN`, `LEX_MARK`.
- `LOOP_CLOSE` is entered by `jp` with `LOOP_OPEN`'s words on the stack (the documented protocol).
- `ex (sp),hl` swaps chains in `if`, `do` and `for`.

**Bugs found during Phase 2 and fixed** (all by the corpus):

- Local initialisers called `CX_ASSIGN.store` with an extra return address between the held lvalue and `CX_POPY`.
- The preprocessor's error label first split `PP_HOOK`'s local labels (an assembly error).

Several test expectations were also wrong and were corrected against C semantics: the value of a function without `return`, and macro self-reference.

## 12. Remaining risks for Phase 3

- **HOME has little slack.** The reserve is 532 B, 20 B above its floor.
  - Most compiler components are at their budget: declarations and statements have 1 B left each; the lexer, symbol table, expressions, code generator, preprocessor and helper core 0 B.
  - Any later change there is paid by shrinking, or by a ledger reallocation from the 20 B above the floor.
- **The Phase 3 library is the largest open estimate.** It has 1,264 B left; `docs/HOME_ROM_INVENTORY.md` §7 estimates 930-1,550 B.
  - `rand`/`srand` already exist.
  - The page-zero trampolines (45 B) and the ISR delta (part of the platform's 138 B, shared with Phase 5's glyphs) are tight but within their estimates.
- **Condition code.** `&&`/`||` as a statement's condition still compute 0/1 and then test it (M1.3). Direct jumps would need expression-compiler bytes; this is a Phase 8 candidate with the `if`/`else` after a `return` (one dead `jp`).
- **Compile speed is 14.4 ms per line** (target 25). The preprocessor's hook costs about 85 T per token: the lexer runs at 428 T/byte, against 405 in M1.2.
- **Compile workspace.** Labels, `case` records and macros are not reclaimed during a compile (§9). Phase 4's capacity table measures what this costs at the limit.
- **Testing.** Only ZEsarUX is used (Phase 9: Fuse, EightyOne, hardware).
