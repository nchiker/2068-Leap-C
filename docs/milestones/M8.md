## 3. Floating point

### 3.1 What was examined

- **The V2 calculator** (`platform/rom/exrom_calc.asm`, 1,929 B, and V2's float formatting, 236 B). It is a reworked port of the Spectrum ROM's calculator: a literal-stream interpreter behind RST `$28` with an 8-slot value stack in `CALC_STACK`, and add, subtract, multiply, divide, pack/unpack, int ↔ float, pi, and the stack operations (exchange, duplicate, delete). It has no comparison, no negation entry, no decimal input, and its formatter has no precision. It works on 32-bit mantissas with unrolled byte moves.
- **The reference compilers** (`docs/C_FEASIBILITY_STUDY.md`). The classic reuse of the Sinclair calculator by a Spectrum C compiler is z88dk's ZX maths option: each C operation pushes its operands on the calculator stack and runs a literal stream. That keeps the 5-byte format but pays the interpreter's setup on every operation, and Leap-C's calculator lives behind a bank switch.

**Decision.** Reuse the calculator's format, RAM, numerical method and formatting, and re-engineer its interface: C needs one operation at a time on known operands, not an interpreter. The re-engineered core replaces the calculator, so nothing numerical is duplicated.

### 3.2 The design

- **Values.** A float is computed in `F_ACC` (a 5-byte cell, always visible). An operand held while another is computed, and a float argument, is a 3-word stack slot (5 bytes and a pad): never in chunk 6, and counted with the pending argument words (at most 32), so the stack's bound holds (`spec.md` §3.2, §4.10).
- **Code.** A binary operation is `call F_PUSH` (the left operand), the right operand into `F_ACC`, `call F_OP / db op`. `F_OP` calls `F_X`, which pages the EXROM in through the depth count inside a `NOBRK` section, runs the core and pages it out. Loads and stores of float objects run in HOME (`F_LD`, `F_LDX`, `F_ST`, `F_STX`, `F_LDK`), where chunk 6 is RAM.
- **The core.** `XF_OP` dispatches on `A` = `FOP_*`: binary operations (`ADD`, `SUB`, `SUBR`, `MUL`, `DIV`, `DIVR`, `CMP`, `CMPR`: the reversed forms avoid a swap when the right operand was computed first), unary ones (`FRI`, `FRU`, `TOI`, `NEG`, `INC`, `DEC`, `PINC`, `PDEC`), `FTOA` and `ATOF`. Arithmetic works on an unpacked 40-bit mantissa (32 bits and a guard byte) and rounds to nearest when it packs.
- **Compile time.** The lexer converts a floating constant through `CX_FOLD` (`FOP_ATOF`) into its 5 bytes; the expression compiler folds constant float operations through the same core, so a folded value equals the run-time one. Decimal input uses an exact table of powers of ten up to 10^13: one correctly rounded operation per constant.
- **Errors.** `F_ERR`: runtime error 6 (`NUMBER TOO BIG`) while a program runs (overflow, division by zero), at the line of the function that failed; compile error 16 or 15 for a constant.

### 3.3 The model

`tools/fpmodel.py` is a bit-exact Python model of every operation (unpack, normalise, add, multiply, divide, compare, conversions, decimal input and output). The float suite (`tools/floattest.py`, suite `float`) runs the ROM's core against it on the production ROM: **5,451 checks** in `make test` (random and edge operands for every operation: signs, zero, exponent extremes, overflow, underflow, rounding ties, every precision of `FTOA`, malformed and extreme constants), 1,876 in `make test-fast`. The host lexer (`tools/clex.py`) uses the model for floating constants, and `tools/gen_floattests.py` generates 53 corpus programs whose expected results come from the model.

| Operation | T-states |
|---|---:|
| add (3.14159265 + 2.71828183) | 2,125 |
| add with a 32-bit alignment shift (1E10 + 3) | 9,773 |
| subtract | 2,942 |
| compare | 1,261 |
| multiply | 20,090 |
| divide | 36,111 |
| negate | 629 |
| int → float / unsigned → float | 1,947 / 1,378 |
| float → int | 4,883 |
| `%.6f` of 3.14159265 / `%.9f` of 1.7E38 (39 digits) | 24,463 / 31,787 |

**Stack.** The float core runs on the program's stack: 32 B below a binary `F_OP`'s operands, 34 B below `printf`'s arguments for `%.9f`, interrupts included: within the 40 B a runtime routine may use (`include/leapc_layout.inc`). `tests/mem/stack/floor_float.c` runs the worst case at the stack floor (40 held int operands, 9 held floats, `printf("%.9f")`): nothing below `$F800` is written.

### 3.6 Deviations and limits

- `?:` with a float and an integer operand is `TYPE MISMATCH` (cast one). Converting the arm compiled first would need code inserted behind it; about 40 B of HOME were judged better kept in the reserve.
- A float converted to an integer type outside its range keeps the low 16 bits of the integer part, with no error (C89: undefined).
- `long double`, `%e`/`%g`, run-time `atof`, and a math library are not in Release 1. `docs/EXAMPLES.md` shows a square root in C.
- The format is the Sinclair one: about 9.6 significant digits, magnitudes 2.9E-39 to 1.7E38, no infinities or NaNs. It is documented as non-IEEE.

## 5. Diagnostics

35 typical mistakes were compiled on the ROM and the error and line checked: a missing `;` (four forms), `}`, `)`; an extra `}`; a misspelt name; an undefined function; argument counts (a program's and a library function's); a string assigned to an `int`; `else` without `if`; `break` outside a loop; an unterminated string; a duplicate local; a value returned from a `void` function; a local array initialiser; a misspelt member; no `main`; `%`, `switch` and pointer conversions on floats; `long`; a declaration after a statement; a keyword as a name; assignment to `const`; calling an `int`; a variable as a `case` label; an undefined label; a bad character; dereferencing an `int`; a string too long for its array.

Every one gets a specific error (`UNDECLARED IDENTIFIER`, `WRONG ARGUMENT COUNT`, `TYPE MISMATCH`, `MISPLACED BREAK`, `NO SUCH MEMBER`, `ASSIGNMENT TO CONST`, `BAD OPERAND TYPE`, `UNDEFINED LABEL`, ...), except the missing tokens: **a missing `;` was reported at the next line**, because the error took the line of the token found instead. The lexer now keeps the previous token's line (`TOK_PLINE`, 2 B of RAM, 6 B), and `CC_EXPECT` reports a missing token there (5 B). All four missing-`;` forms and a `)` missing at a line's end now name the right line (`tests/stmterr/missing_*.c`), and a typed program in the shell puts the cursor on it (`typed-28-missing-semi`). Two older cases that expected the next line were updated. The cost is 32 T per token, about 4% of the compile time.

### 11.3 RAM

The layout is unchanged (`spec.md` §3.1). Two cells are added: `F_ACC` (6 B: the float accumulator and a slot's pad byte) and `TOK_PLINE` (2 B). `LEAPC_CELLS_END` moves from `$5F4A` to **`$5F52`**, leaving 174 B free in the cell area. ## 12. Code audit

`audit-z80` in diff mode (the Phase 7 commit against the working tree), with `make audit`'s pattern scan as a candidate generator; every candidate in the new code checked by hand:

- **Block moves and loops in the float core:** every `ldir` count is a constant (5, 7 or 4); every `djnz` count is non-zero by construction (an exponent difference tested for 0, a shift of 1-127 or 1-32 bits, fixed widths). The formatter's 16 integer bytes hold the largest exponent (127 bits).
- **RAM:** `CALC_STACK` is 40 B in `sysvars.inc`, as the core's `ASSERT` assumes; the overlap of `F_OLD` with the formatter's area is safe (a postfix value is pushed before `printf` runs).
- **Paging:** `F_X` and `CX_XCALL` page through the depth count (tested at depths 0 and 1 by the built-ins); `F_ERR` pages out before `RT_LIBERR`/`CC_ERROR`; `NOBRK` is part of the run state cleared at every start. None of the EXROM-resident parts touches chunk 6 (they use the cells, the compile workspace in the source region, the line store and the screen).
- **Registers:** `BANK_PAGE_EXROM_IN/OUT` destroy only AF; `CX_XCALL` saves AF around the page-out, so its routines' results in F, BC, DE, HL and IX survive. **Found and fixed:** `CX_XCALL`'s comment claimed inputs could pass in A, which the page-in destroys (no caller does; the comment is corrected).
- **Dispatch:** `XC_FOLD` tells float operations from operator tokens by range. **Added:** an `ASSERT` that the ranges cannot overlap.
- **Stack:** the float core's depth is measured (§3.5) and the floor worst case tested; float slots count against the 32 pending words.
- **Compiler stack in `DCL_AUTOINIT`:** the `push af` around `.assign` is balanced (`CX_HOLD` / `CX_POPY` pair inside it).

## 13. Limitations and remaining risks

- **Float speed.** A multiply takes about 5.7 ms and a divide about 10 ms at 3.5 MHz. Float-heavy loops are slow; integer arithmetic is unaffected.
- **The `?:` deviation** (§3.6) is a compile error, never a silent miscompile. An out-of-range float-to-integer conversion gives the low 16 bits without an error, which C89 allows (the behaviour is undefined).
- **Reserves.** HOME has 77 B above its floor, EXROM 77 B. Phase 9's fixes should come from shrinking first.
- **A missing token after a directive line** is reported at the directive's line (rare; documented in `spec.md` §6.3).
- **Emulator only.** As for every phase so far; Phase 9 is the hardware.
