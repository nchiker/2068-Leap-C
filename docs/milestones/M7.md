# Phase 7 — Cassette SAVE/LOAD: milestone report

**Date:** 2026-10-20. **Status: complete.** Every completion criterion of `project_plan.md` §9 is met with measured evidence on real tape signals in ZEsarUX (§1).

- **Source tapes.** `SAVE "name"`, `LOAD "name"` / `LOAD ""` and `VERIFY "name"` keep the source on tape in the stock two-block format with the version word `$8C00`. V2 and Leap-C refuse each other's tapes with `BAD TAPE VERSION` and write nothing. This is tested with tapes made by each ROM's own SAVE.
- **The chunk-6 problem.** It is resolved by the primary design, not the fallback. The block I/O moved to HOME byte for byte (331 B, within its 340 B budget), and the EXROM lost exactly those 331 B. A 14-byte trampoline pages the EXROM out around every block, so `tape_save` and `tape_load` reach any address, chunk 6 included.
- **Failed LOADs.** A failed LOAD now keeps the source whenever the new program fits above it (V2 lost it once a data byte had arrived).
- **Host tool.** `tools/c2tape.py` makes `.tap`/`.tzx` program tapes that load and run.
- **Reserves.** HOME reserve **711 B** (floor 512 B), EXROM reserve **582 B** (floor 256 B).
- **Owner decisions.** None were needed.

- **Baseline:** Phase 6 (`5cf8d80`, `docs/milestones/M6.md`). `spec.md` v0.8 → **v0.9** (§2.1, §2.2, §3.1, §5.8, §6.1, §7, §8, §10).
- **Kept as instructed:**
  - the editor, compiler, runtime and memory architecture, and all Phase 1-6 behaviour (`make test`: 0 failures, §9);
  - the reserve floors;
  - `~/2068-Leap` untouched. It is read only through `git show` / `git archive` of its tag; the V2 reference ROM is built from that copy in `build/v2ref/`.
- **Tools:** sjasmplus 1.23.1; ZEsarUX 13.0 (the patched local build, unchanged) through ts2068-debug's ZRCP client (unchanged); real-tape input through ZRCP `realtape-open`.

## 3. The relocation: measured costs and savings

The plan projected HOME +340 B and EXROM −331 B, "net 0 ROM" (`spec.md` §8.3). Measured on the production images:

| | Projected | Measured |
|---|---:|---:|
| HOME: `STORAGE_SEND_BLOCK` + `STORAGE_RECEIVE_BLOCK` | +340 (budget) | **+331** (127 + 204 B, byte for byte the vendored routines) |
| HOME: the trampoline `TAPE_BLOCK` (EXROM out, the block, EXROM in) | — | **+14** (page0: 153 of 160 B) |
| EXROM: the block I/O removed | −331 | **−331** |
| EXROM: the platform's two block calls, now `ld hl, routine / call TAPE_BLOCK` | — | **+13** |
| **The relocation, net** | 0 | **+27 B** (HOME +345, EXROM −318) |

What Phase 7 added on top of the relocation (features, not relocation cost):

| | Bank | Bytes |
|---|---|---:|
| `tape_save` / `tape_load`: `LIB_TAPE` | HOME | 47 |
| Their EXROM service `SH_LIBTAPE` and its entry jump | EXROM | 71 |
| Their two names in the compiler's binding | EXROM | 24 |
| SAVE's abort (no data block after a stopped header) and LOAD's staging in the block calls | EXROM | 23 |
| SAVE, LOAD, VERIFY: the commands and their reports 292 B, the names 61 B, the record check 40 B, the progress hook 87 B, the texts 133 B, the dispatch and the word matcher 49 B | EXROM | 662 |

Why the relocation is not net 0: the block I/O must run with the EXROM paged *out*, while its caller (the header logic) runs with the EXROM paged *in*. Something has to page the EXROM out and in around each block: the 14-byte trampoline in HOME and the two 6-byte calls of it in the EXROM. The alternative, moving `STORAGE_SAVE` and `STORAGE_LOAD` to HOME as well, would have cost about 450 B more of HOME (they and their helpers measure 462 B in the EXROM).

**The block routines are unchanged**, so their timing is the verified port's. Delta D9 only wraps the file's two halves in `IFNDEF STORAGE_NO_BLOCKS` / `IFNDEF STORAGE_BLOCKS_ONLY`. The routines assemble to the same bytes at a HOME address; both ROM areas are uncontended, so the T-states are those of V2's EXROM copy.

## 4. The tapes

| Block | Program tape (SAVE) | Data tape (`tape_save`) |
|---|---|---|
| header | flag `$00`, type **0**, the name (10 characters, padded with spaces), the length, **`$8C00`**, the length again; XOR checksum | the same with type **3** |
| data | flag `$FF`, the line store exactly as the editor keeps it (`[length:2][text][CR]` per line), XOR checksum | flag `$FF`, the bytes given, XOR checksum |

- **Acceptance** (V2's rule, `STORAGE_LOAD`): the tag and the major must be Leap-C's and the minor at most Leap-C's, checked at the header, before any byte is received. Otherwise `BAD TAPE VERSION`, or -3 for `tape_load`.
- Headers of another type or name are skipped. The search gives up after 15 attempts: about 2 minutes of silence on an empty tape.
- **LOAD is staged.** When the tape's program fits in the room above the current source, the progress hook (at the header) points the data block there (`TAPE_DEST = PROG_END`). The shell then checks the records and moves the program down onto the source. Otherwise the program goes straight into the line store.
- **The record check.** The program must be whole (both checksums) and sound: records of 1-128 bytes, each ending in CR, ending exactly at the length, at least one. A checksum-valid but malformed tape could otherwise mislead the editor and the compiler, which walk the records by their lengths.
- **VERIFY** compares byte for byte and requires the tape to end where the source does. It never writes.
- **A zero-length block cannot be loaded.** The receiver ends after the flag byte, never reading the checksum (V2's port, unchanged). So SAVE refuses an empty source (`NO PROGRAM`), `tape_save` refuses `len` 0 (error 4), and LOAD treats a zero-length tape as unsound.

## 5. The shell's commands

The command word (any case), spaces or none, then a quote. No C line starts that way, so `SAVE` alone, or `save(x);`, is still source. While the tape moves, the status row shows `SAVING name`, or `LOADING` / `VERIFYING` while searching, then `LOADING name` / `VERIFYING name` once the header is found. The hook draws between the blocks, never inside one.

Every outcome is a two-row report as `RUN`'s. Row 23 is always `SOURCE s B  FREE f B`, which shows at a glance that a failed LOAD kept the source.

| Command | Row 22 |
|---|---|
| `SAVE "hello"` | `SAVED hello`, `BREAK`, `BAD NAME`, `NO PROGRAM` |
| `LOAD "hello"`, `LOAD ""` | `LOADED hello` (the tape's name), `LOAD FAILED`, `BAD TAPE VERSION`, `BREAK`, `BAD NAME` |
| `VERIFY "hello"`, `VERIFY ""` | `VERIFIED hello`, `VERIFY FAILED`, `BAD TAPE VERSION`, `BREAK`, `BAD NAME` |

- `BAD NAME`: `SAVE ""`, more than 10 characters, no closing quote, or anything but spaces after it.
- After a LOAD the cursor is on the append line after the last line loaded (V2's rule), and the editor redraws in full.
- **SPACE or BREAK stops a transfer.**
  - The receiver tests SPACE at every edge, the sender after every byte.
  - A SAVE stopped in its header sends no data block (`TAPE_ABORT`): V2 sent it anyway and reported `SAVED`.

## 6. The library

```c
void tape_save(void *name, void *addr, int len);  /* a data tape of len bytes from addr */
int  tape_load(void *name, void *addr, int max);  /* its length, or -1 / -2 / -3 */
```

| Case | `tape_load` returns |
|---|---|
| loaded | the length (≤ `max`) |
| nothing loaded: no such tape before the search gives up, a tape longer than `max`, a bad block before the data | **-1**, `addr` untouched |
| the data block failed after part of it was written | **-2** |
| a version word that is not Leap-C's | **-3**, `addr` untouched |

**Errors and BREAK.**

- A name longer than 10 characters is runtime error 4, and so are an empty name and `len` 0 for `tape_save`.
- `""` loads the next data tape, skipping program tapes.
- BREAK or SPACE during a transfer stops it and ends the program with runtime error 5, at the line of the function that called the tape function. The call is a `NOBRK` section, as `beep()` is.

**Banking.**

1. `LIB_TAPE` (HOME) copies the name's first 11 bytes into `TAPE_NAME` while chunk 6 is still RAM. A name may be a string literal in image region 1.
2. It pages the EXROM in and calls `SH_LIBTAPE`, which checks and pads the name and runs `STORAGE_SAVE` / `STORAGE_LOAD`.
3. Their blocks come back to HOME through `TAPE_BLOCK` with chunk 6 = RAM again.
4. IX (the frame base) is kept.

**Measured** (`lib-stack`): `tape_load` uses at most **28 B** of stack below its first argument over a whole transfer, interrupts between blocks included. That is within the 40 B a library routine may use, and the stack margin of `include/leapc_layout.inc` is unchanged.

While a block moves, interrupts are off (the stock routines), so `frames()` does not count meanwhile.

## 7. Design decisions

1. **The primary resolution.** HOME had the room: 749 B reserve, plus the 340 B budgeted. The bounce-buffer fallback would have bounded data blocks by a buffer's size and doubled their copying.
2. **One trampoline for both blocks, the header logic in the EXROM** (§3).
3. **The staged LOAD** (Leap-C's addition). V2 lost the old program as soon as a data byte had arrived, and cassette loads fail often enough for that to matter. Here the old source survives any failure when both fit (in practice, any program up to about 9 KB loaded over one up to about 9 KB); the cost is about 40 B: the decision at the header, the redirected data block, the move down.
4. **The record check** guards the editor and the compiler against a malformed tape (§4).
5. **SPACE stops a SAVE for real** (§5): one cell, `TAPE_ABORT`, read by the EXROM's call of the sender. The vendored `STORAGE_SAVE` is unchanged.
6. **The progress hook** (V2's `STORAGE_PROGRESS_HOOK`, which V2's production shell never installed). It shows the found tape's name during `LOAD ""`, as the stock ROM does.
7. **`tape_load`'s results** distinguish an untouched destination (-1, -3) from a partly overwritten one (-2).
8. **Real signals in the tests** (§9.2): SAVE is captured at the MIC line without stopping the machine, and LOAD reads ZEsarUX's real-tape input. V2's tests intercepted SAVE before its pulses.

### 9.2 Harness

- **Real tape in** (`Machine.tape_insert`): ZRCP `realtape-open` plays a `.rwa`, `.tap` or `.tzx` into the EAR bit in emulated time, one sample per scan line.
  - **ZEsarUX's autoload.** Inserting a tape resets the CPU and arms an autoload that types `J""` ENTER into the keyboard reads as soon as the PC reaches `$11F8`. In the Leap-C HOME, that address is a compiler routine.
  - The harness disarms it at once: the trigger runs for one instruction, then its key sequence is drained by about 2,000 reads of a keyboard row it never answers.
  - A second trigger must then press nothing (checked on the ENTER row). The booted snapshot is restored next, and the tape plays on.
  - `--noautoload` cannot be used: with it nothing starts playback under ZRCP.
- **SAVE captured** (`Machine.tape_capture`): each of the five `out (PORT_ULA), a` of HOME's `STORAGE_SEND_BLOCK` gets a breakpoint whose action prints `TSTATESP*16+(A&8)` on ZEsarUX's standard output (line-buffered to a file) without stopping. `tools/tapes.py` turns the edges into blocks and measures every pulse. The same signal becomes a `.rwa` for LOAD.
- **Synthesised tapes** (`tools/tapes.Tape`): the stock timing with faults built in. Their pilots are at least the data block's stock 3,223 pulses: the receiver waits about 1 s after the first edge before it counts 256 leader cycles, so shorter pilots time out.
- **Banking invariants** (`tools/memguard.py`): two more, "a tape block sent / received with the EXROM paged in", armed with the others through every transfer of the suite and the corpus.
- **The V2 reference ROM** (`tools/v2ref.sh`, `make v2ref`): `git archive` of the tag, V2's own `make build`, the release hashes checked.

## 12. Code audit

`make audit` (the z80-skills pattern scan), and every hint in the new code checked by hand:

- **`ldir`:**
  - `LIB_TAPE`: BC = 11.
  - `SH_HEADER_NAME`: BC = 10.
  - LOAD's move: BC = the tape's length, never 0, because the record check refuses an empty block first. A zero count would copy 64 KB.
- **`ei` in `SH_TAPE_DONE`:** intentional. The tape routines disable interrupts, and `TAPE_BLOCK`'s paging re-enables them between blocks.
- **Stack balance:** every new routine. `TAPE_BLOCK` (`push`/`pop af` twice), `LIB_TAPE` (IX kept; the error path leaves through `RT_ERROR`, which resets SP), `SH_LOAD_V`, `SH_NAME`, `SH_TAPE_HOOK` (its staging path), `SH_TAPE_RECV`, `SH_LIBTAPE`.
- **Flags:** `SH_CHECK_STORE` takes Z from `sbc hl, bc` and carry from the `add hl, bc` that follows (`add` keeps Z). `SH_LOAD_IO` maps `STORAGE_LOAD`'s A (0 / `$FF` / `$FE`) to `TR_*` with `neg / inc a` (an assembly-time ASSERT checks it). `TR_VERSION` is tested before the abort flag B, which is undefined on that path.
- **Registers:**
  - The `STORAGE_RECEIVE_BLOCK` contract keeps A, carry and Z through `TAPE_BLOCK`'s paging (`push af`).
  - AF' is not live across the hook: `STORAGE_LOAD` uses it only inside the receiver.
  - IX and DE survive `BANK_PAGE_EXROM_*`.
- **Found by the audit and fixed:**
  - After a reordering, the BREAK report fell through into `BAD NAME` (caught again by three tape cases).
  - `SH_LIBTAPE` let `SH_NAME` destroy the length in DE (caught by the first `tape_save` capture).

## 13. Limitations and remaining risks

- **Emulator only.** The signals are ZEsarUX's: SAVE's at the `out` instructions (the analogue MIC output is not modelled) and LOAD's through its real-tape input, quantised to a scan line (224 T). A physical cassette (levels, noise, wow and flutter, the recorder) is Phase 9's.
- **The direct LOAD.** A program too big to arrive above the source, failing after part of it arrived, still empties the source (V2's rule). With a source near the line store's room, `NEW` first, then LOAD.
- **The search's give-up** takes about 2 minutes on a tape without the program (V2's bound); BREAK ends it at once.
- **No interrupts while a block moves.** `frames()` stops counting meanwhile, and keys pressed are not seen.
- **`tape_load` writes where it is told.** Loading over the stack, the system variables or the program itself is the program's mistake (C has no bounds checks).
- **Zero-length blocks** cannot be loaded (the receiver), so they are refused at SAVE / `tape_save`.
- **`VERIFY ""`** verifies against the first program tape found.
